# 发布检查

适用于维护者首次上传和后续发布。当前没有自动发布、签名、公证或部署流程；CI 只检查源码。

## 发布前

1. 核对 README、SUPPORT 和 PRIVACY 与最终代码一致。区分代码支持、实际验证和尚未实现的能力，不把计划写成已支持。
2. 运行 DEVELOPMENT 中的离线测试、独立输出构建、Swift 计算和读取进程检查。界面变动还应检查真实交互及 demo 截图。
3. 运行 `python3 scripts/package_source.py --check`，核对公开清单。新增文件必须同步更新清单。
4. 人工检查待提交内容，排除登录、缓存、日志、个人路径和真实截图。按需使用独立凭据扫描工具；清单检查不等于凭据扫描，也不会扫描 Git 历史。
5. 确认 MIT 版权与许可声明正确保留；复用外部源码或素材时另行核对许可证，不把外部服务授权包含在本项目许可中。
6. 为正式版本更新 CHANGELOG、`build.py` 中的显示版本及构建号；有实际远程仓库后，再创建对应提交和 tag。首次公开前仍保持 Unreleased，不编造发布历史。

## 源码包验证

```sh
python3 scripts/package_source.py
```

在新目录解压 ZIP，按 README 构建、运行离线检查，并检查本地文档链接和图片。上传仓库时解压成源文件；发布页可提供源码 ZIP，但不要将机器绑定的本地 `.app` 冒充通用安装包。

## GitHub 仓库检查

- 仓库描述和 README 展示正确，LICENSE 被识别为 MIT。
- Issue/PR 模板可用，安全报告入口以实际设置为准；按需开启私密漏洞报告和 GitHub 提供的秘密扫描/推送保护。
- 查看当前提交的 Actions 运行结果；本地通过不能代替远端结果。
- 首次公开前核对当前文件和已有 Git 历史。忽略规则不会删除已提交的敏感数据。
- 下载一次实际发布的源码验证内容。若只上传了仓库但未创建 Release，应如实描述为源码仓库。

仓库可见性、远端发布和账户设置由维护者选择，本检查清单不会自动执行这些操作。面向新手的浏览器步骤见 [GITHUB_UPLOAD.md](GITHUB_UPLOAD.md)。
